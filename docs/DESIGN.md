# Agent Chat 初版设计

常规私聊和群聊共用同一个消息流。输入框提供 Agent 名录；真人会话只有点名时才创建任务，首次点名加入临时成员，完成后退出，也可通过成员面板留在会话。用户在发送前选择传给 Agent 的历史范围。Agent 的发言和任务状态显示在同一对话中。

「独立 AI 团队」是只属于创建者的群。把当前启用的 Agent 加为成员，用户可以删减和设置负责人。点名时按指定成员执行，未点名由负责人接单。负责人按需从本群选择成员派子任务，受任务深度、并发和预算约束。运行时原生子 Agent 通过适配器使用，平台子任务独立记录状态。停止父任务时传播取消，移除成员时取消它在本群参与的活跃任务。

初版用 Node.js、SQLite 和自带 Web 客户端交付可本地运行的应用。用实际的会话权限、消息标识和任务状态验证体验，避免给本地原型引入独立 IM 集群。若需要成熟推送、复杂漫游和大量在线连接，再将消息层迁移到 OpenIM。浏览器里预览小游戏或小工具，代码在隔离 iframe 中运行。工程类工具执行需要支持受限工作区的运行时；应用进程本身不执行模型生成的 shell 指令。

DeepSeek API 为共享默认推理。Qwen 为可配后端。Codex 订阅只接本机，服务部署时用团队自己的 API。Claude、Pi、DeepSeek Harness 和其他运行时通过 CLI 或 HTTP 适配器接入。Agent 能力以适配器实际支持为准。未配置项不进入可用目录。

验收流程：两个独立登录窗口互聊 → 临时 @Agent 并查看回复和退出 → 一方新建独立 AI 团队 → 分工制作小游戏 → 预览并下载产物。还要验证成员及产物权限、重启恢复、停止任务和服务端账号隔离。
